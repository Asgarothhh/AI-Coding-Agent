# AGENTS.md — правила работы агентов в репозитории

## Что это за проект

openJiuwen Challenge 2026: batch-агент, который решает пакет задач в рамках бюджета
токенов. Стек: Python 3.11, ядро только на стандартной библиотеке,
`openjiuwen==0.1.20.post1` для доступа к LLM. Контейнер работает с read-only
корневой ФС (`HOME=/tmp`), сеть доступна только до LLM-прокси.

Формула стоимости: `prompt_tokens/10 + completion_tokens`; reasoning-токены
считаются как completion. Точка входа: `python run_agent.py --tasks-dir /data/tasks`.

## Источник истины

- `openspec/` — спеки и изменения (единственный канонический источник требований).
- `specs/001-token-estimator/` — исходные материалы (не редактировать в обход OpenSpec).
- `README.md` — описание текущего поведения и результаты прогонов.

При расхождении приоритет такой:
`openspec/specs` > `openspec/changes` > `specs/001-token-estimator` > `README.md`.

Если README противоречит спеке — прав код и спека, README приводится в соответствие.

## Рабочий цикл

1. `/opsx:explore` — разведка: читаем спеку, код, тесты; ничего не меняем.
2. `/opsx:propose` — оформляем change с delta-спекой (`ADDED`/`MODIFIED`/`REMOVED`).
3. `/opsx:apply` — реализация строго по tasks.yaml изменения.
4. `/opsx:archive` — после приёмки: спека обновляется, change уходит в архив.

Правки кода только через change: нет change — нет правки. Новое требование
сначала попадает в delta-спеку, потом в код. Один change — одна цель.

## Что нельзя

- Перерегистрировать агента: регистрация неизменяема, менять её нельзя.
- Коммитить секреты, `team.json`, API-ключи, токены и приватные URL.
- Ходить в сеть в режиме прогноза (`--offline` обязателен для замеров).
- Писать вне `tasks/OUT/` и `/tmp`; корень образа read-only.
- Править тестовые файлы во время решения задачи (хеши тестов защищены).
- Делать `git push` без явного разрешения владельца репозитория.
- Удалять или переписывать чужие файлы, включая файлы других лейнов.

## Зоны записи по лейнам

| Лейн | Что пишет |
|---|---|
| A, упаковка | `Dockerfile`, `entrypoint.sh`, `scripts/*`, `.dockerignore` |
| B, оценщик | `harness/estimator.py`, `harness/policy.py`, `harness/planner.py`, `harness/registry.py`, `harness/calibration.json`, тесты оценщика и политики |
| C, солверы | `harness/patch.py`, `harness/solvers/*.py`, `harness/memory.py`, `harness/runner.py`, тесты патчей и солверов |
| D, эксперименты | `eval/**`, тесты метрик |
| F, документация | `README.md`, `openspec/**`, `specs/**` |

`runner.py` — зона лейна C. Лейн B может добавить туда не больше одной строки-хука
и только после того, как C закончил.

## Обязательные команды перед коммитом

```bash
python3.11 -m unittest discover -s tests              # unit
python3.11 -m unittest discover -s tests/contract     # контрактные
python3.11 run_agent.py --tasks-dir examples/task-dir --offline --mutation-repair --max-workers 1  # offline 8/8
openspec validate --strict
git grep -nE 'oc_sk_|BEGIN OPENSSH|API_KEY=|sk-[A-Za-z0-9]{20,}' -- ':!tests' ':!*.md'
```

Офлайн-прогон должен давать 8/8 решённых, score 20. `openspec validate --strict`
обязателен для каждого изменения. Найденные совпадения grep надо разобрать, а не
проигнорировать.

## Определение готовности задачи

Задача считается готовой, когда одновременно выполнено:

1. тест написан и падает до фикса, проходит после;
2. команда проверки из tasks.yaml прогнана и её вывод приложен;
3. артефакт (код, отчёт, JSON) записан в ожидаемое место;
4. сделан коммит с сообщением `T00X: <краткое описание>`;
5. измеренные числа внесены в отчёт, а не заявлены словами.

## Стоп-условия

- Три неудачные попытки подряд → откат к последнему зелёному состоянию, статус `blocked`.
- Израсходовано 150k токенов на эксперименты → стоп до решения владельца.
- Наступило 12.11 18:00 → заморозка: только фиксы, ломающие приёмку.
- Секрет попал в дифф → стоп, отзыв ключа, очистка истории до пуша.
- Базовые тесты сломаны → стоп: сначала зелёный baseline, потом новая работа.

## Подключение нейросетевого оценщика

Оценщик регистрируется в реестре (`harness/registry.py`) под отдельным именем,
включается переменной `OJ_ESTIMATOR=neural`. Требования: работает офлайн
(веса в образе), размер модели ≤ 5 МБ, при любой ошибке — откат на эвристику,
покрытие контрактными тестами и сравнение MAPE с базовой версией в отчёте.
