## 2. P0 — блокеры

### P0-1. Официальная команда не передаёт бюджет

В `specs/001-token-estimator/spec.md:986-994` официальная команда:

```bash
docker run ... \
  -e LLM_BASE_URL -e LLM_API_KEY \
  ...
  hack:latest /app/run_agent.py --tasks-dir /data/tasks
```

`BUDGET`/`OJ_TOKEN_BUDGET` там нет. `run_agent.py:179` вызывает `BudgetProvider`, а `harness/budget.py:196-200` при отсутствии бюджета вне `--offline` завершает процесс:

```text
error: no token budget configured: pass --budget, set OJ_TOKEN_BUDGET
(or BUDGET), or run with --offline for the local test default.
```

Проверено: `exit 2`, ни одного `answer.txt`. README добавляет `-e BUDGET` (строка 469), но это уже не официальная команда из спеки. Имя переменной организаторами не подтверждено; harness принимает только `OJ_TOKEN_BUDGET` и `BUDGET`. Публичные участники используют разные имена (встречается `TOKEN_BUDGET`). Если жюри использует другое имя — результат тот же: 0.

**Что делать:** подтвердить имя у организаторов; поддержать несколько имён; если подтверждения нет — обсудить документированный fallback. Иначе официальная команда §15.3 даёт 0.

### P0-2. Права на каталог задач: R3 падает целиком

`Dockerfile` запускает контейнер от root, но `--cap-drop ALL` убирает `CAP_DAC_OVERRIDE`. Root без capability не может писать в каталог, принадлежащий другому uid с правами 0755.

В R3 `harness/runner.py:362` вызывает `store.ensure_placeholder(task)` для каждой задачи до планирования; `harness/store.py:187-202` создаёт пустые `answer.txt` без `try/except`. Проверено на копии с `chmod -R a-w`:

```text
fatal: PermissionError: [Errno 13] Permission denied:
  '/tmp/.../coding_0003/.answer.txt.<rand>.tmp'
exit 2
answer.txt: 0
```

В Docker-тесте с чужим uid 0755: **solved 0/8, failed 8, answer.txt 0**. При этом `scripts/run_local.sh:42` делает `chmod -R a+rwX` и маскирует проблему; README:450 говорит про `--user`, которого в скрипте нет. `README.md:490` и `eval/results/docker.md` предупреждают, но решения нет.

**Что делать:** получить подтверждение прав mount у организаторов; прогнать официальную команду на копии с натуральными правами; не добавлять capabilities. Если жюри распаковывает задачи от root или монтирует 0777 — работает; если от непривилегированного пользователя с umask 022 — 0 баллов.

### P1-2. Coding-солвер ложно объявляет pytest-тесты пройденными

`harness/solvers/coding.py:104-136` запускает каждый тест как `python -B test_mylib.py`. Для unittest-файлов с `if __name__ == "__main__": unittest.main()` это работает. Для pytest-style файла:

```python
def test_add():
    assert add(2, 3) == 5
```

Python импортирует файл и выходит с кодом 0; тест не выполняется. Проверено на remote:

```text
run.passed = True
solve answer = DONE
notes = tests already pass
```

При скрытом наборе с pytest-тестами агент запишет `DONE`, не исправив баг, и получит 0 за задачу. Нужно `python -m unittest discover` / pytest и трактовать «0 выполненных тестов» как провал.

### P1-3. Data-analysis выбирает не ту метрику

`harness/solvers/data_analysis.py:92-116`:
