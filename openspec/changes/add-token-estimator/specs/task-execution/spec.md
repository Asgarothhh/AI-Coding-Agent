# Выполнение задач

## Purpose
Гарантировать предсказуемую обработку любой задачи — от известного детерминированного типа до полностью неизвестного — без падений процесса, без лишних расходов и с ответом только при реальном успехе.

## ADDED Requirements

### Requirement: Универсальный путь для неизвестного типа
Система SHALL решать задачу неизвестного типа одним обращением к модели с извлечением итогового ответа.

#### Scenario: Неизвестный тип решается
- **WHEN** встречается тип задачи, для которого нет специализированного солвера
- **THEN** задача решается универсальным путём, и в трассировке указывается использованный путь

#### Scenario: Модель недоступна
- **WHEN** задача неизвестного типа поступает при отключённых обращениях к модели
- **THEN** задача помечается как нерешённая без ответа, а остальные задачи продолжают обрабатываться

### Requirement: Восстановление ответа из нестрогого формата
Система SHALL извлекать ответ из прозы, обёрнутого или обрезанного структурированного вывода модели.

#### Scenario: Ответ окружён пояснением
- **WHEN** модель возвращает ответ внутри прозы или в обёртке с пояснениями
- **THEN** извлекается именно значение ответа, и задача считается решённой

#### Scenario: Структурированный вывод повреждён
- **WHEN** ответ модели невозможно разобрать ни одним допустимым способом
- **THEN** задача помечается как нерешённая, процесс не падает, а причина попадает в диагностику

### Requirement: Атомарная запись только при успехе
Система SHALL записывать ответ атомарно и только для успешно решённой задачи.

#### Scenario: Успешная задача
- **WHEN** задача решена и проверена
- **THEN** файл ответа появляется целиком, содержа одну строку ответа без пояснений

#### Scenario: Запись прервана
- **WHEN** процесс прерывается во время записи ответа
- **THEN** на месте ответа не остаётся частично записанного файла: либо прежнее содержимое, либо ничего

#### Scenario: Задача не решена
- **WHEN** задача пропущена, невыполнима или провалена
- **THEN** файл ответа не создаётся и не перезаписывается

### Requirement: Один JSON в стандартном выводе
Система MUST выводить в стандартный вывод ровно один JSON-объект, а всю диагностику направлять в поток ошибок.

#### Scenario: Обычный прогон
- **WHEN** прогон завершён
- **THEN** стандартный вывод содержит единственный разбираемый JSON-объект со сводкой, а посторонние сообщения находятся в потоке ошибок

#### Scenario: Подробный режим
- **WHEN** включён подробный вывод диагностики
- **THEN** объём диагностики растёт только в потоке ошибок, а стандартный вывод по-прежнему содержит один JSON-объект

### Requirement: Детерминированные типы без модели
Система SHALL решать детерминированные типы задач без обращений к модели и с нулевым расходом.

#### Scenario: Офлайн-прогон
- **WHEN** прогон выполняется с отключёнными обращениями к модели на наборе детерминированных задач
- **THEN** все такие задачи решаются, а израсходованное количество токенов равно нулю

#### Scenario: Обращение к модели не требуется
- **WHEN** задача детерминированного типа проходит проверку на выполнимость
- **THEN** она решается специализированным путём, и счётчик обращений к модели остаётся нулевым

### Requirement: Пропуск невыполнимых задач
Система SHALL пропускать задачи с оценкой невыполнимости не ниже порога, не расходуя бюджет и не создавая ответа.

#### Scenario: Задача выше порога
- **WHEN** оценка невыполнимости задачи не ниже заданного порога
- **THEN** задача пропускается с перечнем причин, расход по ней равен нулю, ответ не создаётся

#### Scenario: Задача ниже порога
- **WHEN** оценка невыполнимости ниже порога
- **THEN** задача передаётся в решение, а не отбрасывается по признаку невыполнимости

### Requirement: Запрет сети не считается требованием сети
Система MUST отличать запрет на использование интернета от требования интернета при оценке выполнимости задачи.

#### Scenario: Инструкция запрещает сеть
- **WHEN** инструкция содержит «no internet and no LLM calls» или «work offline; no network access»
- **THEN** задача не помечается как требующая интернета и допускается к решению

#### Scenario: Инструкция требует сеть
- **WHEN** инструкция содержит URL, download, web search или «internet access is required»
- **THEN** задача помечается как требующая интернета и может быть пропущена

### Requirement: Работа в неизменяемой файловой системе
Система MUST работать при корневой файловой системе, доступной только для чтения, записывая данные лишь в каталог задач, каталог вывода и временный каталог.

#### Scenario: Прогон при чтении-only корне
- **WHEN** контейнер запускается с корневой файловой системой только для чтения
- **THEN** прогон завершается успешно, ответы и журналы появляются в разрешённых каталогах, а запись вне них не выполняется

#### Scenario: Попытка записи вне разрешённых путей
- **WHEN** компонент пытается писать за пределами разрешённых каталогов
- **THEN** попытка отклоняется или перенаправляется, а прогон не прерывается

### Requirement: Изоляция сбоя одной задачи
Система SHALL продолжать обработку остальных задач при исключении, падении или превышении времени в одной задаче.

#### Scenario: Исключение в задаче
- **WHEN** при решении одной задачи возникает непредвиденное исключение
- **THEN** задача помечается как проваленная с причиной, а остальные задачи обрабатываются до конца

#### Scenario: Таймаут задачи
- **WHEN** решение одной задачи превышает отведённое время
- **THEN** задача останавливается и помечается как пропущенная, а общий прогон укладывается в общий лимит времени
