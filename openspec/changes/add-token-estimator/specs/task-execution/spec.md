# Выполнение задач и сохранение результата

## Purpose
Гарантировать, что все задачи читаются корректно, каждая получает обязательный файл ответа, а прогон продолжается при сбое отдельной задачи. Поведение должно соответствовать фактическому контракту задачи, а не предположениям.

## ADDED Requirements

### Requirement: Загрузка всех задач и награды
Система MUST загружать все доступные задачи до первого обращения к модели, MUST читать награду из данных задачи и MUST сохранять неизвестные поля без потерь.

#### Scenario: Полный набор задач
- **WHEN** запуск начинается с каталогом задач
- **THEN** система считывает все задачи, их награды и исходные данные до первого вызова модели

#### Scenario: Незнакомое поле в данных задачи
- **WHEN** данные задачи содержат поле, неизвестное текущей версии
- **THEN** поле сохраняется без изменений и не приводит к ошибке разбора

### Requirement: Обязательный файл ответа
Для каждой задачи система MUST обеспечивать наличие файла ответа по пути `<TASKS>/<task_id>/answer.txt` и MUST NOT использовать иной путь как основной.

#### Scenario: Каталог без файла ответа
- **WHEN** в каталоге задачи отсутствует файл ответа на старте
- **THEN** система создаёт его и заполняет после подтверждённого решения

#### Scenario: Решение сохранено сразу
- **WHEN** задача решена и проверена
- **THEN** файл ответа записывается немедленно, не дожидаясь завершения остальных задач

### Requirement: Атомарная запись ответа
Система SHALL записывать ответ атомарно и MUST NOT считать решённой задачу с пустым файлом ответа.

#### Scenario: Запись завершена
- **WHEN** ответ записан
- **THEN** файл существует, содержит ожидаемый текст и доступен для чтения

#### Scenario: Пустой файл
- **WHEN** файл ответа существует, но пуст
- **THEN** задача не учитывается как решённая

### Requirement: Служебные файлы вне каталога задачи
Система MUST размещать диагностические и служебные файлы только во временном каталоге или в потоке диагностики и MUST NOT создавать их в каталоге задачи.

#### Scenario: Диагностика прогона
- **WHEN** система записывает трассы и отладочные данные
- **THEN** они попадают во временный каталог или в поток диагностики, а не в каталог задачи

#### Scenario: Содержимое каталога задачи
- **WHEN** задача завершена
- **THEN** в её каталоге нет служебных файлов, кроме требуемого файла ответа

### Requirement: Универсальный решатель по фактической схеме
Универсальный решатель MUST использовать реальную схему данных задачи и её инструкцию и MUST NOT навязывать ответ в формате JSON, если задача этого не требует.

#### Scenario: Задача со свободным форматом ответа
- **WHEN** инструкция задачи не требует JSON
- **THEN** решатель формирует ответ в требуемом инструкцией формате

#### Scenario: Неизвестный тип задачи
- **WHEN** тип задачи не распознан
- **THEN** задача не роняет прогон, а обрабатывается универсальным решателем по фактической инструкции

### Requirement: Изоляция файловой системы
Система MUST работать при корневой файловой системе только для чтения и MUST записывать данные только в каталог задач и во временный каталог.

#### Scenario: Запуск в ограниченном контейнере
- **WHEN** система запущена с корневой файловой системой только для чтения
- **THEN** прогон выполняется без ошибок записи вне разрешённых каталогов

#### Scenario: Попытка записи вне разрешённых мест
- **WHEN** компонент пытается писать за пределы каталога задач и временного каталога
- **THEN** такое поведение не допускается и не влияет на сохранение ответов

### Requirement: Сеть только к разрешённому адресу модели
Система MUST направлять сетевые обращения только на адрес модели, заданный окружением, и MUST NOT использовать локальные модели или внешние адреса моделей.

#### Scenario: Обращение к модели
- **WHEN** системе требуется ответ модели
- **THEN** запрос уходит только на заданный адрес шлюза моделей

#### Scenario: Отсутствие загрузок в runtime
- **WHEN** система работает во время соревновательного прогона
- **THEN** она не скачивает модели, пакеты и данные из сети

### Requirement: Изоляция сбоя задачи
Сбой одной задачи MUST NOT прерывать прогон остальных задач, а причина сбоя MUST фиксироваться.

#### Scenario: Исключение в решателе
- **WHEN** обработка задачи завершилась исключением
- **THEN** задача получает статус неудачи с причиной, а следующие задачи продолжают выполняться

#### Scenario: Задача без ответа
- **WHEN** задача завершилась неудачей
- **THEN** остальные задачи и общий учёт бюджета остаются корректными
