# Политика бюджета

## Purpose
Превращать прогноз в дисциплинированное решение о приёме, отклонении и остановке задач, чтобы бюджет не превышался, а очки на единицу расхода росли.

## ADDED Requirements

### Requirement: Явный вердикт по каждой задаче
При планировании система SHALL выдавать по каждой задаче вердикт «принять» или «отклонить» с машиночитаемой причиной отклонения.

#### Scenario: Задача проходит по бюджету
- **WHEN** ожидаемая стоимость с запасом укладывается в доступный остаток и теневая цена расхода оправдана ожидаемой наградой
- **THEN** задача получает вердикт «принять» и попадает в очередь выполнения

#### Scenario: Отклонение по стоимости
- **WHEN** ожидаемая выгода задачи не покрывает теневую цену её ожидаемой стоимости
- **THEN** задача получает вердикт «отклонить» с причиной «дорого» и не выполняется

#### Scenario: Отклонение как невыполнимая
- **WHEN** оценка невыполнимости задачи превышает порог
- **THEN** задача получает вердикт «отклонить» с причиной «невыполнима» и не расходует бюджет

### Requirement: Запрет перерасхода и неприкосновенность резерва
Система MUST NOT допускать расход, который превысил бы остаток бюджета за вычетом резерва.

#### Scenario: Резерв остаётся нетронутым
- **WHEN** доступный остаток равен резерву
- **THEN** ни одна новая задача не принимается, а зарезервированная часть остаётся неизменной

#### Scenario: Вызов не помещается в остаток
- **WHEN** очередной вызов модели превысил бы остаток после вычета резерва
- **THEN** вызов не выполняется, задача останавливается с указанной причиной, а итоговый перерасход остаётся нулевым

### Requirement: Остановка по верхней границе
Система SHALL останавливать задачу, когда верхняя граница прогноза превышает лимит задачи или доступный остаток бюджета.

#### Scenario: Верхняя граница выше лимита задачи
- **WHEN** верхняя граница прогноза превышает установленный лимит на задачу
- **THEN** задача останавливается до первого вызова, а причина остановки попадает в трассировку

#### Scenario: Верхняя граница выше остатка
- **WHEN** в ходе выполнения верхняя граница оставшейся стоимости превышает остаток бюджета
- **THEN** дальнейшие вызовы по задаче прекращаются, а уже полученный результат сохраняется

### Requirement: Приоритет по ожидаемой выгоде на единицу стоимости
Система SHALL упорядочивать приём задач по отношению ожидаемой награды к ожидаемой стоимости, а не по порядку поступления.

#### Scenario: Приоритет выгодных задач
- **WHEN** в очереди есть задачи с разным отношением награды к стоимости при ограниченном бюджете
- **THEN** первой принимается задача с наибольшим отношением, а менее выгодные отклоняются при исчерпании остатка

#### Scenario: Политика «берём всё» проигрывает
- **WHEN** симуляция бюджета 20k сравнивает политику приоритета с приёмом всех задач подряд
- **THEN** политика приоритета даёт не меньший score и ноль перерасходов

### Requirement: Учёт стоимости промпта и завершения
Система MUST считать стоимость каждого вызова из токенов промпта и завершения по фиксированным весам контракта, учитывая рассуждение только один раз.

#### Scenario: Рассуждение не считается дважды
- **WHEN** ответ модели содержит отдельный счётчик рассуждения и пустой счётчик завершения
- **THEN** рассуждение учитывается как завершение, и итоговая стоимость не удваивается

#### Scenario: Провайдер не вернул расход
- **WHEN** ответ не содержит данных о расходе токенов
- **THEN** применяется детерминированная оценка по тексту, и такая стоимость помечается как оценочная

### Requirement: Остановка по невыгодности продолжения
Система SHALL останавливать выполнение задачи, когда ожидаемая остаточная выгода не превышает ожидаемую остаточную стоимость.

#### Scenario: Безнадёжная задача останавливается раньше лимита
- **WHEN** после очередной попытки ожидаемая остаточная выгода ниже ожидаемой остаточной стоимости
- **THEN** задача останавливается, не исчерпывая лимит попыток, и причина фиксируется в трассировке

#### Scenario: Потеря решаемости ограничена
- **WHEN** ранняя остановка применяется на отложенной выборке
- **THEN** доля решённых задач падает не более чем на допустимую величину, а расход на безнадёжные прогоны снижается

### Requirement: Детерминированные решения
Система SHALL принимать одинаковые решения при одинаковых прогнозе, остатке, лимите, резерве и награде.

#### Scenario: Повторный расчёт
- **WHEN** одно и то же решение запрашивается дважды с одинаковыми входами
- **THEN** вердикт, причина и остаток после решения совпадают

#### Scenario: Нулевой бюджет
- **WHEN** остаток бюджета равен нулю
- **THEN** все задачи отклоняются с причиной «бюджет исчерпан», и ни одна не запускается

### Requirement: Отклонение не расходует бюджет
Система SHALL сохранять расход по отклонённой задаче нулевым и не изменять остаток бюджета.

#### Scenario: Отклонённая задача не влияет на остаток
- **WHEN** задача отклонена до выполнения
- **THEN** её расход равен нулю, остаток бюджета не меняется, а вердикт с причиной попадает в итоговую сводку

#### Scenario: Отклонение после частичного расхода
- **WHEN** задача отклонена уже после одного оплаченного вызова
- **THEN** потраченное остаётся списанным, новый расход не появляется, а причина отклонения указывает на исчерпание лимита
