# Починка кода

## Purpose
Повышать долю решённых coding-задач при меньшем расходе, применяя точечные правки и проверяя каждую из них тестами, которые нельзя изменять.

## ADDED Requirements

### Requirement: Точечная правка вместо перезаписи файла
Система SHALL применять правку только при однозначном совпадении указанного фрагмента, а при промахе — оставлять файл неизменным и возвращать ближайший подходящий фрагмент как подсказку для следующей попытки.

#### Scenario: Уникальное совпадение фрагмента
- **WHEN** модель возвращает фрагмент для замены, который встречается в файле ровно один раз
- **THEN** правка применяется, файл изменяется только в этом месте, а остальное содержимое остаётся байт в байт прежним

#### Scenario: Неоднозначное совпадение
- **WHEN** фрагмент для замены встречается в файле более одного раза
- **THEN** правка не применяется, файл остаётся неизменным, а модель получает сообщение о необходимости уточнить фрагмент

#### Scenario: Фрагмент не найден
- **WHEN** фрагмент для замены отсутствует в файле с точностью до незначащих различий
- **THEN** правка не применяется, а в следующую попытку передаётся ближайший по сходству участок файла как подсказка

### Requirement: Проверка сразу после правки
Система SHALL запускать проверку сразу после применения правки и передавать первую обнаруженную ошибку дословно в следующую попытку.

#### Scenario: Ошибка возвращается без пересказа
- **WHEN** после применённой правки проверка падает
- **THEN** текст первой ошибки без изменений попадает в следующее обращение к модели

#### Scenario: Проверка прошла
- **WHEN** после правки все связанные проверки проходят
- **THEN** цикл правок прекращается и результат считается готовым к выдаче

### Requirement: Неизменность тестов
Система MUST сохранять тестовые файлы неизменными и восстанавливать любые изменения, внесённые по ходу работы, до выдачи результата.

#### Scenario: Тест изменён по ходу работы
- **WHEN** содержимое тестового файла отличается от зафиксированного в начале работы
- **THEN** файл восстанавливается, а результат задачи не принимается как решённый

#### Scenario: Тесты не тронуты
- **WHEN** работа завершается успешно
- **THEN** все тестовые файлы совпадают с исходными по содержимому и ни один тест не был ослаблен или пропущен

### Requirement: Лимит попыток правки
Система SHALL ограничивать число попыток правки заданным лимитом и прекращать работу по его достижении.

#### Scenario: Лимит исчерпан
- **WHEN** число попыток достигает установленного лимита, а проверки всё ещё падают
- **THEN** работа прекращается без ответа, а задача помечается как нерешённая

#### Scenario: Нулевой лимит
- **WHEN** лимит попыток равен нулю
- **THEN** ни одно обращение к модели не выполняется, и задача сразу помечается как нерешённая

### Requirement: Два варианта правки
Система SHALL сравнивать два независимых варианта правки и выбирать проходящий вариант с меньшим изменением, а при равенстве — вариант, выбранный детерминированно.

#### Scenario: Проходит только второй вариант
- **WHEN** первый вариант не проходит проверки, а второй проходит
- **THEN** применяется второй вариант, и задача считается решённой

#### Scenario: Проходят оба варианта
- **WHEN** оба варианта проходят проверки
- **THEN** применяется вариант с меньшим объёмом изменений, а при равном объёме выбор одинаков при повторном запуске

#### Scenario: Не проходит ни один вариант
- **WHEN** оба варианта не проходят проверки
- **THEN** изменения откатываются, и следующая попытка начинается с исходного состояния файлов

### Requirement: Ответ только при прохождении тестов
Система MUST NOT выдавать ответ по coding-задаче, пока все связанные тесты не проходят.

#### Scenario: Тесты падают
- **WHEN** хотя бы один связанный тест завершается неуспешно
- **THEN** ответ не записывается, а задача помечается как нерешённая с указанием первой ошибки

#### Scenario: Проходит только часть тестов
- **WHEN** часть тестов проходит, а часть падает
- **THEN** задача считается нерешённой, и частичный успех не выдаётся как ответ

### Requirement: Откат при неудаче
Система MUST возвращать изменённые исходники в состояние до первой правки, если ни одна попытка не прошла проверку.

#### Scenario: Откат после серии неудач
- **WHEN** все попытки правки исчерпаны без успешной проверки
- **THEN** каждый изменённый файл возвращается к содержимому, зафиксированному перед первой правкой

#### Scenario: Откат не затрагивает посторонние файлы
- **WHEN** выполняется откат
- **THEN** файлы, которые не изменялись в ходе работы, остаются нетронутыми
