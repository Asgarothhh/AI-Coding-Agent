# Правка кода и защита проверок

## Purpose
Обеспечить безопасный цикл исправления кода, при котором меняются только исходники, проверки остаются неизменными, а ответ сохраняется лишь после подтверждённого прохождения. Провал оформляется честно, без фиктивного ответа.

## ADDED Requirements

### Requirement: Сначала детерминированное решение
Система MUST сначала проверять, покрывается ли задача детерминированным решением, и MUST NOT начинать цикл правки кода, если задача решается без обращения к модели.

#### Scenario: Задача покрыта известным шаблоном
- **WHEN** входные данные соответствуют проверенному шаблону
- **THEN** ответ формируется без вызова модели и цикл правки не запускается

#### Scenario: Шаблон не подошёл
- **WHEN** входные данные не соответствуют ожидаемому шаблону
- **THEN** задача передаётся в цикл правки без уверенно неверного ответа

### Requirement: Правка только исходников
Система SHALL изменять только исходные файлы задачи и MUST NOT изменять проверяющие файлы, а неизменность проверок MUST подтверждаться сравнением хешей.

#### Scenario: Изменение затрагивает тесты
- **WHEN** предложенная правка изменяет проверяющий файл
- **THEN** такая правка отклоняется и не применяется

#### Scenario: Проверка целостности
- **WHEN** цикл правки завершился
- **THEN** хеши проверяющих файлов совпадают с исходными, а изменённые проверки восстановлены

### Requirement: Ограниченное число попыток
Система MUST ограничивать число попыток правки заранее заданным пределом и MUST прекращать цикл при его достижении.

#### Scenario: Предел попыток достигнут
- **WHEN** число попыток достигло установленного предела без успешной проверки
- **THEN** цикл завершается со статусом неудачи

#### Scenario: Успех до предела
- **WHEN** проверка проходит раньше достижения предела
- **THEN** цикл завершается успешно и лишние попытки не выполняются

### Requirement: Проверка после каждой правки
Система MUST проверять результат после каждой правки и SHALL передавать в следующую попытку точную первую диагностическую ошибку с компактным контекстом.

#### Scenario: Проверка выявила ошибку
- **WHEN** после применения правки проверка завершилась ошибкой
- **THEN** первая диагностическая ошибка попадает в следующий запрос к модели

#### Scenario: Проверка прошла
- **WHEN** после применения правки проверка завершилась успешно
- **THEN** дополнительные попытки не запрашиваются

### Requirement: Однозначное применение правки
Система MUST применять правку только при однозначном совпадении контекста и MUST NOT применять её при отсутствии совпадений или при нескольких подходящих местах.

#### Scenario: Совпадений нет
- **WHEN** контекст правки не найден в файле
- **THEN** правка не применяется, а модели возвращается ближайший фрагмент для уточнения

#### Scenario: Несколько кандидатов
- **WHEN** контекст совпадает в нескольких местах
- **THEN** правка не применяется и запрашивается уточнённый вариант

### Requirement: Ответ только после подтверждения
Система MUST сохранять ответ как решение только при подтверждённом прохождении доступной проверки и MUST NOT считать решением непустой текст модели.

#### Scenario: Проверка подтвердила результат
- **WHEN** доступная проверка задачи проходит после правки
- **THEN** ответ сохраняется как решение задачи

#### Scenario: Проверка недоступна
- **WHEN** автоматическая проверка отсутствует, но подтверждён требуемый формат сдачи
- **THEN** ответ сохраняется только при выполнении этого формата

### Requirement: Честный провал
При исчерпании попыток или отсутствии подтверждения система MUST помечать задачу как failed, MUST NOT сохранять ответ и MUST NOT учитывать её как решённую.

#### Scenario: Все попытки неудачны
- **WHEN** ни одна попытка не привела к прохождению проверки
- **THEN** задача получает статус failed, файл ответа не создаётся

#### Scenario: Проверки были подменены
- **WHEN** обнаружено, что проверяющие файлы отличались от исходных
- **THEN** результат не принимается, задача помечается как failed
