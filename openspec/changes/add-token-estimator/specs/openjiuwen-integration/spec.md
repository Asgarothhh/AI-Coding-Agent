# Интеграция с openJiuwen

## Purpose
Обеспечить, что решение построено на Python SDK openJiuwen Core и все обращения к модели идут через официальные интерфейсы к разрешённым моделям. Использование SDK должно быть доказано реальным вызовом, а не установкой пакета.

## ADDED Requirements

### Requirement: Только Core SDK в runtime
Система MUST использовать Python SDK openJiuwen Core и MUST NOT включать WorkSwarm или jiuwenswarm в runtime.

#### Scenario: Сборка образа
- **WHEN** формируется runtime-образ
- **THEN** в нём присутствует только Core SDK с закреплённой версией и нет прикладного WorkSwarm

#### Scenario: Проверка состава зависимостей
- **WHEN** проверяется окружение запуска
- **THEN** среди зависимостей нет приложений уровня WorkSwarm

### Requirement: Только разрешённые модели
Система MUST использовать только четыре разрешённые модели и MUST NOT обращаться к локальным моделям или внешним адресам моделей.

#### Scenario: Выбор модели
- **WHEN** система выбирает модель для задачи
- **THEN** выбор ограничен списком разрешённых моделей

#### Scenario: Попытка использовать другую модель
- **WHEN** конфигурация или код ссылается на модель вне списка
- **THEN** запуск завершается понятной ошибкой конфигурации

### Requirement: Единый шлюз вызовов модели
Все обращения к модели MUST проходить через единый шлюз, реализованный на официальных интерфейсах Core, и MUST NOT выполняться в обход него.

#### Scenario: Вызов из решателя
- **WHEN** решателю нужен ответ модели
- **THEN** вызов выполняется через общий шлюз, а не через собственный клиент

#### Scenario: Прямой вызов SDK
- **WHEN** компонент пытается обратиться к модели напрямую
- **THEN** такой путь отсутствует в решении и не используется при сборке

### Requirement: Сопоставление параметров окружения
Шлюз MUST передавать адрес и ключ из переменных окружения модели в соответствующие параметры подключения SDK и MUST NOT отключать проверку TLS ради успешного соединения.

#### Scenario: Запуск с параметрами окружения
- **WHEN** система запущена с заданными адресом и ключом модели
- **THEN** шлюз использует именно эти значения при подключении

#### Scenario: Проверка TLS
- **WHEN** устанавливается соединение с адресом модели
- **THEN** проверка TLS остаётся включённой

### Requirement: Обязательный smoke-тест
До основной реализации система MUST пройти smoke-тест через реальный шлюз, подтверждающий фактический вызов, получение исходных данных о расходе, представление reasoning-токенов и отсутствие скрытых дополнительных вызовов.

#### Scenario: Успешный smoke-тест
- **WHEN** выполняется минимальный реальный вызов разрешённой модели
- **THEN** сохраняются исходные данные о расходе и подтверждается, что вызов ушёл на заданный адрес

#### Scenario: Скрытые вызовы
- **WHEN** при одном запросе SDK инициирует дополнительные обращения к модели
- **THEN** это обнаруживается на smoke-тесте до начала основной реализации

#### Scenario: Smoke-тест не проходит
- **WHEN** SDK не может работать с заданным шлюзом
- **THEN** блокер фиксируется явно и не маскируется обходным клиентом

### Requirement: Отсутствие молчаливого переключения
Ошибка шлюза MUST NOT приводить к молчаливому переключению на другой адрес модели или другую модель, а MUST приводить к явной ошибке.

#### Scenario: Ошибка соединения
- **WHEN** обращение к разрешённой модели завершилось ошибкой
- **THEN** задача получает явную причину сбоя без подмены адреса или модели

#### Scenario: Недоступная модель
- **WHEN** выбранная разрешённая модель недоступна
- **THEN** система сообщает об этом и не обращается к неразрешённой альтернативе

### Requirement: Нормализация расхода без двойного учёта
Система MUST нормализовать данные о расходе из фактических полей ответа и MUST NOT учитывать reasoning-токены дважды.

#### Scenario: Reasoning включён в выход
- **WHEN** reasoning-токены уже входят в выходной расход
- **THEN** они не прибавляются повторно

#### Scenario: Reasoning передан отдельно
- **WHEN** reasoning-токены переданы отдельно и не входят в выходной расход
- **THEN** они добавляются ровно один раз

#### Scenario: Данные о расходе отсутствуют
- **WHEN** ответ не содержит данных о расходе
- **THEN** это фиксируется как отдельный случай и не подменяется нулевым значением
