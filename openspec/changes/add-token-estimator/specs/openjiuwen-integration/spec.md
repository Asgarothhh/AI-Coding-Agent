# Интеграция с openJiuwen

## Purpose
Обеспечить реальное и проверяемое использование openJiuwen в рабочем пути, чтобы заявленная интеграция подтверждалась артефактами, а не декларацией, и при этом не ломала запуск при отсутствии пакета.

## ADDED Requirements

### Requirement: Модельный слой через SDK
Система SHALL использовать модельный слой openJiuwen как основной транспорт обращений к модели при наличии пакета.

#### Scenario: Пакет установлен
- **WHEN** рабочий путь запускается в окружении с установленным пакетом openJiuwen
- **THEN** обращения к модели идут через модельный слой SDK, а не через встроенный клиент

#### Scenario: Явно запрошен SDK без пакета
- **WHEN** запуск явно требует бэкенд openJiuwen, а пакет отсутствует
- **THEN** запуск завершается понятной ошибкой до обработки задач, без молчаливой подмены транспорта

### Requirement: Проверка пути интеграции реальным вызовом
Система MUST подтверждать выбранный путь интеграции реальным вызовом модели через прокси, а не только установкой пакета.

#### Scenario: Низкоуровневый путь
- **WHEN** проверяется путь через модельный слой
- **THEN** выполняется реальный вызов, фиксируются latency и usage, а результат сохраняется в отчёте

#### Scenario: Путь WorkflowAgent и Runner
- **WHEN** проверяется путь через WorkflowAgent и Runner
- **THEN** выполняется реальный вызов или фиксируется недоступность с причиной, а решение о выборе пути попадает в отчёт

#### Scenario: Только установка пакета
- **WHEN** доказательство ограничивается установкой пакета без реального вызова
- **THEN** интеграция считается неподтверждённой

### Requirement: Фактический бэкенд в диагностике и итоговом JSON
Система SHALL сообщать фактический бэкенд в потоке ошибок и в поле llm_backend итогового JSON, различая запрошенный и фактический варианты.

#### Scenario: Автоматический выбор при установленном пакете
- **WHEN** выбран автоматический режим и пакет доступен
- **THEN** в потоке ошибок появляется ровно одна строка с именем фактического бэкенда, а итоговый JSON содержит llm_backend со значением openjiuwen

#### Scenario: Автоматический откат
- **WHEN** выбран автоматический режим и пакет недоступен
- **THEN** используется встроенный клиент, llm_backend отражает фактический выбор, а запрошенный вариант сохранён рядом для сверки

### Requirement: Доказательство использования
Система MUST прилагать к отчёту версию пакета, строку фактического бэкенда из потока ошибок, значение llm_backend и отчёт harness-прогона.

#### Scenario: Полный комплект доказательств
- **WHEN** доказательство интеграции собрано
- **THEN** в нём присутствуют все четыре артефакта, и версия пакета совпадает с закреплённой в зависимостях

#### Scenario: Не хватает артефакта
- **WHEN** отсутствует хотя бы один из четырёх артефактов
- **THEN** интеграция считается неподтверждённой, и это явно указано в отчёте

### Requirement: Откат на встроенный клиент
Система SHALL продолжать работу на встроенном клиенте при отсутствии SDK, не меняя поведение вызывающего кода.

#### Scenario: Пакет удалён из окружения
- **WHEN** прогон выполняется в окружении без openJiuwen
- **THEN** задачи обрабатываются встроенным клиентом, а функциональные проверки проходят без установки пакета

#### Scenario: Встроенный клиент не выдаёт себя за SDK
- **WHEN** используется встроенный клиент
- **THEN** итоговый JSON и диагностика называют его собственным именем, а не openjiuwen

### Requirement: Логи SDK не засоряют стандартный вывод
Система SHALL направлять логи SDK в каталог, доступный для записи, и не выводить их в стандартный вывод.

#### Scenario: Корневая файловая система только для чтения
- **WHEN** рабочий путь запускается при корневой файловой системе только для чтения
- **THEN** логи SDK попадают во временный каталог, а прогон не пытается писать в каталоги образа

#### Scenario: Предупреждения SDK
- **WHEN** SDK формирует предупреждение или ошибку
- **THEN** сообщение попадает в поток ошибок, а стандартный вывод по-прежнему содержит один JSON-объект

### Requirement: Swarm-совместимая пакетная обёртка
Система SHALL предоставлять пакетную обёртку для окружения Swarm, которая не открывает сетевых портов и не меняет ход решения задач.

#### Scenario: Запуск через обёртку
- **WHEN** пакетный прогон запускается через обёртку Swarm
- **THEN** обрабатывается тот же набор задач с тем же результатом, а порты не открываются

#### Scenario: Отчёт harness видит окружение Swarm
- **WHEN** отчёт harness собирается из-под окружения Swarm
- **THEN** в нём присутствуют признаки этого окружения, и они не подделаны вручную

#### Scenario: Обёртка не требуется
- **WHEN** требование Swarm не заявлено организаторами
- **THEN** обёртка не влияет на рабочий путь и пакетный прогон выполняется напрямую

### Requirement: DeepAgent только при измеримом выигрыше
Система MUST NOT подключать DeepAgent к рабочему пути без измеримого выигрыша по score или стоимости на сопоставимом наборе задач.

#### Scenario: Выигрыша нет
- **WHEN** эксперимент с DeepAgent не даёт измеримого улучшения score или стоимости
- **THEN** отказ фиксируется в отчёте, а рабочий путь остаётся прежним

#### Scenario: Выигрыш подтверждён
- **WHEN** эксперимент показывает измеримый выигрыш при сопоставимом расходе
- **THEN** подключение оформляется отдельным решением с приведённым сравнением стоимости и score

### Requirement: Честность заявлений об интеграции
Система MUST NOT выдавать встроенный клиент за openJiuwen, подделывать признаки окружения Swarm или записывать ключи доступа в логи и репозиторий.

#### Scenario: Подмена бэкенда
- **WHEN** сравнение строки бэкенда и поля llm_backend расходится с фактическим транспортом
- **THEN** прогон считается недостоверным, а результат интеграции не принимается

#### Scenario: Ключ попал в лог
- **WHEN** в диагностике или артефактах обнаруживается ключ доступа
- **THEN** прогон считается проваленным, а ключ подлежит отзыву и удалению из истории
