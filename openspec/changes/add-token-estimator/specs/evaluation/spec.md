# Оценка результатов и экспериментов

## Purpose
Определять, какая реализация действительно лучше, по итоговой сумме награды при заданном бюджете, а не по точности прогноза. Точность оценщика используется только как диагностика.

## ADDED Requirements

### Requirement: Главный критерий оценки
Система MUST оценивать реализацию по сумме награды за подтверждённо решённые задачи при заданном бюджете и MUST требовать нулевого числа перерасходов.

#### Scenario: Сравнение двух реализаций
- **WHEN** две реализации сравниваются на одном наборе задач и при одном бюджете
- **THEN** лучшей признаётся реализация с большей суммой награды за решённые задачи

#### Scenario: Зафиксирован перерасход
- **WHEN** в прогоне обнаружен хотя бы один запрос, отправленный без достаточного резерва
- **THEN** результат прогона не принимается как успешный независимо от суммы награды

### Requirement: Метрики ошибки как диагностика
Система SHALL использовать MAPE, WAPE и MAE только как диагностические показатели и MUST вычислять MAPE только на задачах с положительным фактическим расходом.

#### Scenario: Положительный фактический расход
- **WHEN** выборка содержит задачи с положительным фактическим расходом
- **THEN** метрики ошибки считаются по этим задачам и сопровождаются размером выборки

#### Scenario: Нулевой фактический расход
- **WHEN** часть задач имеет нулевой фактический расход
- **THEN** они исключаются из MAPE и показываются отдельно как доля задач с нулевым расходом

### Requirement: Разделение данных по задачам
Система MUST разделять данные на обучающую и отложенную части по идентификатору задачи или семейству и MUST NOT делить их по отдельным строкам вызовов.

#### Scenario: Одна задача в нескольких прогонах
- **WHEN** задача имеет несколько записей вызовов
- **THEN** все её записи попадают только в одну часть выборки

#### Scenario: Проверка пересечения
- **WHEN** эксперимент завершён
- **THEN** пересечение задач между обучающей и отложенной частями отсутствует

### Requirement: Сравнение политик на одном наборе
Система MUST сравнивать не менее трёх политик планирования на одном и том же наборе задач и бюджете.

#### Scenario: Сравнение политик
- **WHEN** готовится отчёт о выборе реализации
- **THEN** в нём присутствуют результаты минимум трёх политик на одинаковых входных данных

#### Scenario: Разные условия сравнения
- **WHEN** политики сравниваются на разных наборах или бюджетах
- **THEN** такое сравнение не считается доказательством превосходства

### Requirement: Бюджетные сценарии
Система SHALL прогонять несколько бюджетных сценариев и MUST помечать синтетические сценарии как синтетические, а главный сценарий MUST соответствовать реальному бюджету соревнования.

#### Scenario: Синтетический бюджет
- **WHEN** используется бюджет, не подтверждённый организаторами
- **THEN** он помечается как синтетический сценарий

#### Scenario: Основной сценарий
- **WHEN** формируется итоговый отчёт
- **THEN** главным считается сценарий с реальным бюджетом соревнования

### Requirement: Принятие улучшения
Улучшение MUST приниматься только при воспроизводимом выигрыше на отложенных данных при сопоставимом бюджете и MUST NOT приниматься на основании одного удачного прогона.

#### Scenario: Воспроизводимый выигрыш
- **WHEN** новая реализация повторно показывает не худшую сумму награды на отложенных задачах
- **THEN** она может быть включена по умолчанию

#### Scenario: Выигрыш не воспроизводится
- **WHEN** повторный прогон не подтверждает преимущество
- **THEN** остаётся более простая базовая реализация

### Requirement: Фиксация отрицательных результатов
Система MUST фиксировать отрицательные и неопределённые результаты экспериментов вместе с условиями их проведения.

#### Scenario: Метод не дал выигрыша
- **WHEN** экспериментальный метод не улучшил основной критерий
- **THEN** результат фиксируется как отрицательный с указанием условий и размера выборки

#### Scenario: Данных недостаточно
- **WHEN** выборка слишком мала для вывода о превосходстве
- **THEN** результат фиксируется как неопределённый и не используется как основание для включения метода
