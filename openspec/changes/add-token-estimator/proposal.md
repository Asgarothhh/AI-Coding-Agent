# Proposal

## Why

Регламент openJiuwen Challenge 2026 начисляет баллы за сумму `reward` правильно
решённых задач при одном общем бюджете токенов. Побеждает не самый точный
прогноз стоимости, а решение, которое успевает решить больше дорогих задач и ни
разу не выходит за бюджет. Спецификация v4.0 смещала цель в MAPE, конформные
интервалы и исследование 19 теорий; на оставшиеся два дня это создавало риск не
дойти до сборки и отборочного прогона.

Главные риски v4.0, которые это изменение обязано снять:

- **per-task cap** — индивидуальный лимит задачи, которого нет в регламенте;
  он произвольно отсекал бы дорогие, но выгодные задачи;
- **гонка бюджета** — несколько сессий могли одновременно зарезервировать один
  и тот же остаток;
- **неопределённый источник бюджета** — runtime подставлял выдуманное число;
- **OUT вместо `answer.txt`** — обязательный артефакт подменялся необязательным
  каталогом диагностики;
- **недоказанный openJiuwen** — установленный пакет выдавался за интеграцию без
  реального вызова через SDK;
- **4 CPU** — проект проверялся под 8 ядер, которых у жюри может не быть;
- **зоопарк теорий** — T4/T5/T8/T11/T16/T17/T18 не могли быть подтверждены на
  8 примерах и добавляли платные вызовы.

Источник истины — `specs/001-token-estimator/spec.md` v5.0, которая явно
заменяет v4.0. Приоритет: регламент → v5.0 → этот change.

## What Changes

- **BudgetProvider и BudgetLedger**: размер общего бюджета получается только из
  подтверждённого источника (`BudgetProvider`); локально — `OJ_TOKEN_BUDGET`.
  `BudgetLedger` атомарно делает `reserve`/`settle`/`release_failed` и держит
  инвариант `spent + reserved <= B`.
- **Отказ от per-task cap**: индивидуального лимита задачи нет. Все решения
  принимаются относительно общего остатка; единственный запас —
  `planning_reserve` (5–10% бюджета) на ошибку прогноза.
- **OpenJiuwenGateway на Core SDK**: реальные вызовы идут через
  `openjiuwen==0.1.20.post1` (`ModelClientConfig`, `ModelRequestConfig`,
  `LLMComponent`/`WorkflowAgent`, `Runner`), а не через скрытый HTTP-клиент.
  Smoke-тест через прокси обязателен до основной реализации.
- **Четыре разрешённые модели**: `qwen3.8-27b`, `qwen3.8-27b-noreason`,
  `qwen3.6-35b-a3b`, `qwen3.6-35b-a3b-noreason`; локальные и внешние LLM
  запрещены. `noreason` включается только по измеренному выигрышу.
- **UsageNormalizer**: единая формула `output + input/10`, reasoning считается
  один раз; поддержаны оба формата полей прокси и отсутствие usage.
- **Простой оценщик с онлайн-коррекцией**: иерархия медиан
  `(solver, task_type, model)` → `(solver, task_type)` → глобальная → эвристика
  по длине prompt; `low/medium/high` confidence по числу наблюдений. Факт
  обновляет только in-memory множитель текущего запуска, калибровочный файл не
  переписывается.
- **Планировщик по ожидаемому reward**: `v_i = reward_i × P_solve_i`,
  `c_i = upper_cost_i`; выбор набора под бюджет и время, порядок — по `v_i/c_i`.
  Reward не используется как признак сложности.
- **Детерминированные и generic солверы**: покрытые шаблоны решаются без LLM;
  неизвестный `task_type` уходит в generic solver с фактической инструкцией и
  структурой `task.json`, а не роняет процесс.
- **Coding repair**: SEARCH/REPLACE с требованием уникального совпадения,
  возврат точной первой ошибки в следующий промпт, максимум 3 итерации, хеши
  проверяющих файлов защищены и восстанавливаются.
- **`answer.txt` только в каталоге задачи**: атомарная запись
  `temp → flush → fsync → os.replace`; пустой файл создаётся на старте, но не
  считается решённой задачей.
- **Диагностика вне каталога задачи**: структурированный stderr и `/tmp`;
  `predictions.jsonl`/`trace.jsonl`/`OUT` не требуются, пока организаторы не
  подтвердят смонтированный путь.
- **Docker под 4 CPU и лимиты**: проектирование и тесты под 4 ядра (до
  письменного подтверждения иного), read-only rootfs, `tmpfs 2g`, 16 ГБ RAM,
  образ < 4 ГБ, сборка < 1000 с, никаких скачиваний в runtime.
- **Тесты и fake proxy**: unit и контрактные тесты, сценарий 100 задач на
  fake proxy, тест конкуренции Ledger, smoke четырёх моделей через прокси.
- **Три разработчика**: зоны файлов и интеграционный контракт раздела 13
  фиксируются до параллельной работы; новые P1/P2-идеи не входят в основную
  версию без выигрыша на отложенных данных.

## Capabilities

### New Capabilities

- `token-estimation`: детерминированный офлайн-прогноз `expected_cost` и
  `upper_cost` по solver/type/model с confidence, fallback-медианами и
  онлайн-коррекцией; SHALL NOT выполнять LLM-вызовы и SHALL NOT заявлять
  статистических гарантий.
- `budget-policy`: один общий бюджет, атомарные `reserve`/`settle`/`release`,
  запрет отправки без резерва, `planning_reserve` и решения
  `accept`/`reject_cost`/`reject_time`; SHALL держать ноль перерасходов.
- `coding-repair`: безопасный SEARCH/REPLACE (0 или >1 совпадений — не
  применять), цикл проверки с дословной ошибкой, лимит итераций и защита
  проверяющих файлов; MUST NOT позволять солверу менять тесты.
- `task-execution`: загрузка всех задач и reward, маршрутизация solver,
  generic fallback для неизвестного типа, определение `impossible` только по
  проверяемой причине, атомарное сохранение `answer.txt`.
- `evaluation`: baseline и отборочный прогон, fake proxy на 100 задач,
  TotalScore/solve rate/cost per solved, диагностические MAE/MdAPE/WAPE,
  split по `task_id`/семейству.
- `openjiuwen-integration`: production-путь через Core SDK, маппинг
  `LLM_BASE_URL`/`LLM_API_KEY`, четыре разрешённые модели, raw usage из прокси
  и воспроизводимый smoke-тест; MUST NOT обходить SDK скрытым клиентом.

## Impact

- `harness/budget.py`, `harness/usage.py`, `harness/openjiuwen_gateway.py` —
  BudgetProvider, Ledger, нормализатор usage, шлюз.
- `harness/estimator.py`, `harness/planner.py`, `harness/policy.py`,
  `harness/calibration.json` — прогноз, планирование и решения.
- `harness/runner.py`, `harness/solvers/*`, `harness/patch.py`,
  `harness/triage.py` — маршрутизация, coding и generic пути.
- `harness/store.py`, `harness/task.py`, `run_agent.py` — атомарная запись
  `answer.txt`, разбор `task.json`, точка сборки компонентов.
- `tests/` — unit, контрактные тесты, fake proxy, Ledger contention и smoke
  openJiuwen; существующие baseline-тесты не переписываются.
- `Dockerfile`, `.dockerignore`, `entrypoint.sh`, `scripts/*`, lock-файл —
  воспроизводимая сборка под 4 CPU, read-only rootfs, digest базового образа.
- `README.md` — фактическая команда, версия SDK, способ получения бюджета,
  статусы AC и все `NOT VERIFIED`.
- Не трогаем: существующую регистрацию агента, `team.json`, `specs/**`,
  файлы других change и любые чужие артефакты. **BREAKING** нет: CLI и формат
  `answer.txt` сохраняются.
