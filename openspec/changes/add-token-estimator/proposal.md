# Proposal

## Why

Соревнование оценивает сумму баллов за правильно решённые задачи при общем
бюджете токенов, а не точность прогноза саму по себе. Поэтому цель изменения —
поднять score и удержать ноль перерасходов; прогноз стоимости, интервалы и
калибровка нужны только как инструменты планировщика: они решают, какие задачи
брать, в каком порядке и когда останавливаться. MAPE — диагностическая метрика,
а не критерий успеха.

Сейчас харнесс решает задачи и аккуратно списывает фактический `usage`, но
прогнозировать не умеет: `planner.estimate_cost()` — эвристика 40/60/80/1800 для
сортировки, без калибровки, интервала и логирования. Поэтому решения
«принять/отклонить» и ранняя остановка не управляемы, а перерасходы не
исключены. Второй разрыв — отсутствие запасного пути: для неизвестного
`task_type` задача просто падает. Третий — нет доказательства использования
openJiuwen SDK и нет второго полигона, чтобы не переобучиться на восьми
официальных примерах.

## What Changes

- **Estimator**: `harness/estimator.py` — признаки задачи, приор по типу (T1),
  калибровка «символы в токены» (T13), приоры из lorne (T19), логлинейная модель
  (T3), модель цикла починки (T4), онлайн-обновление остатка (T5), конформные
  интервалы (T6); прогноз детерминирован, офлайн, ≤ 50 мс.
- **Policy**: `harness/policy.py` — экономика принять/отклонить с теневой ценой
  бюджета (T7), оптимальная остановка (T10), проба модели (T16); у каждого
  вердикта есть причина.
- **Patch protocol**: `harness/patch.py` — SEARCH/REPLACE вместо перезаписи
  файла целиком, лестница применения от точного совпадения до AST-якоря и
  сходства ≥ 0,92, подсказка `closest_window` при промахе (T14).
- **Verify-feedback**: `harness/solvers/coding.py` — синтаксис → линтер →
  связанные тесты, первая строка `FAILED` дословно уходит в следующий промпт,
  лимит 6 итераций, хеши тестовых файлов защищены (T15); опционально два
  варианта правки (T17) и память эпизодов (T18).
- **Generic solver**: `harness/solvers/generic.py` — один вызов LLM и
  восстановление ответа/JSON для неизвестного типа задачи (ТР-07), битый JSON
  не роняет процесс.
- **Calibration и учёт**: `harness/calibration.json` версионируется,
  `predictions.jsonl` пишет признаки, прогноз, интервал, уверенность, теорию и
  версию модели; в `trace.jsonl` добавляются прогноз, факт и id теории.
- **Evaluation**: `eval/` — синтетика 40–60 задач (seed 42), `ground_truth.jsonl`,
  метрики MAPE/MdAPE/Pinball/PICP@90/MPIW, симуляции бюджета 20k/50k/100k,
  абляции признаков (T12), бейзлайны B0–B4.
- **Registry**: `harness/registry.py` и переменные `OJ_ESTIMATOR`, `OJ_POLICY`,
  `OJ_SOLVER`; неизвестное имя даёт понятную ошибку, замена реализации не меняет
  вызывающий код (ТР-17…ТР-19).
- **openJiuwen proof**: `scripts/verify_openjiuwen.py` и
  `tests/test_openjiuwen_backend.py` фиксируют версию пакета, строку
  `LLM backend: openjiuwen`, поля `llm_backend` в summary и отсутствие секретов
  в логах; DeepAgent подключается только при измеримом выигрыше.
- **Docker и запуск**: `Dockerfile`, `entrypoint.sh`, `scripts/build.sh`,
  `scripts/run_local.sh` — non-root прогон при read-only rootfs, `HOME=/tmp`,
  без сети; параметризованный entrypoint под неизвестную официальную команду.
- **Docs**: `README.md` — методология, таблица теорий с числами, команды
  воспроизведения, ограничения и зафиксированные отрицательные результаты.
- **Second polygon**: `eval/tasks-lorne/` — 16–18 задач с манифестом и
  структурными проверками вместо grep; отложенная выборка для выбора модели.

## Capabilities

### New Capabilities

- `token-estimation`: прогноз стоимости задачи с интервалом, уверенностью и
  факторами; калибровка только на обучающей части; детерминизм и офлайн.
- `budget-policy`: вердикт принять/отклонить/остановить, неприкосновенность
  бюджета, ноль перерасходов, причина у каждого решения.
- `coding-repair`: патчи через поиск/замену, петля проверки с возвратом ошибки,
  неизменность тестовых файлов.
- `task-execution`: маршрутизация задач по типам, универсальный fallback для
  неизвестного типа, атомарная запись ответа.
- `evaluation`: синтетика и второй полигон, метрики, бейзлайны, симуляции
  бюджета, абляции.
- `openjiuwen-integration`: runtime через openJiuwen SDK (L1), выбор бэкенда,
  доказательство использования, DeepAgent только по результату эксперимента.

## Impact

- `harness/`: новые `estimator.py`, `policy.py`, `patch.py`, `registry.py`,
  `solvers/generic.py`, `memory.py`, `calibration.json`; правки `planner.py`,
  `runner.py`, `solvers/coding.py`; `ojiuwen_llm.py` и `llm.py` без смены
  контракта.
- `tests/`: новые `test_estimator.py`, `test_policy.py`, `test_patch.py`,
  `test_generic_solver.py`, `test_registry.py`, `test_openjiuwen_backend.py`;
  расширение `test_coding.py` и контрактных тестов. Существующие тесты не
  переписываются.
- `eval/`: `make_synthetic.py`, `fit.py`, `run_eval.py`, `metrics.py`,
  `probe.py`, `priors.py`, `import_lorne.py`, `deepagent_probe.py`,
  `tasks-lorne/`, `results/`.
- `Dockerfile`, `entrypoint.sh`, `scripts/*`: non-root, read-only rootfs,
  параметризация команды запуска.
- `README.md` и `specs/**` (документация; спеки пишет отдельный специалист).
- Совместимость: контракт `answer.txt`, бюджет и CLI не ломаются, поэтому
  **BREAKING** нет.
- Вне скоупа: секреты, `team.json`, перерегистрация агента, смена модели на
  каждом вызове, fine-tuning, UI, новые runtime-зависимости.
